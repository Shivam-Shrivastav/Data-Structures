# Trapping Rain Water (LeetCode 42)

**Pattern:** Two Pointers + Prefix/Suffix Maximums

---

# 1. Problem Statement

Given an array `height[]` where each element represents the height of a bar of width `1`, compute **how much rainwater can be trapped** after raining.

Water can only be trapped **between taller bars**.

### Constraints

* `1 <= height.length <= 2 * 10^4`
* `0 <= height[i] <= 10^5`
* Need an **O(N)** solution.

# 4. Intuition & Pattern Recognition

## Signals

Whenever you see

* Elevation map
* Water trapped
* Heights
* Left boundary + Right boundary

Think:

> Every position needs the tallest wall on both sides.

Water at index `i` is

```text

```

# 6. Brute Force

For every index

Find

* maximum on left
* maximum on right

Then compute water.

```python
water = 0

for i in range(n):

    leftMax = max(height[:i+1])
    rightMax = max(height[i:])

    water += min(leftMax, rightMax) - height[i]
```

### Complexity

```text
Time  : O(N²)

Space : O(1)
```

---

# Better Solution (Prefix & Suffix Arrays)

Precompute

```text
leftMax[]

rightMax[]
```

Then

```text
water += min(leftMax[i], rightMax[i]) - height[i]
```

### Complexity

```text
Time : O(N)

Space : O(N)
```

# 7. Optimal Solution (Two Pointers)

## Key Observation

At any moment,

```text
If leftMax <= rightMax

then left side decides water.

Because even if the right side becomes taller later,

minimum(leftMax, rightMax) is still leftMax.
```

Similarly,

```text
If rightMax < leftMax

right side decides.
```

So we never need complete prefix/suffix arrays.

---

### Diagram

```text
L                          R

0 1 0 2 1 0 1 3 2 1 2 1

leftMax = 1
rightMax = 2

Since leftMax < rightMax

Compute water on LEFT

Move L
```

---

### Python

```python
class Solution:
    def trap(self, height: List[int]) -> int:

        left = 0
        right = len(height) - 1

        leftMax = 0
        rightMax = 0

        water = 0

        while left < right:

            if height[left] < height[right]:

                # Update left boundary
                if height[left] >= leftMax:
                    leftMax = height[left]
                else:
                    # Water trapped above current left bar
                    water += leftMax - height[left]

                left += 1

            else:

                # Update right boundary
                if height[right] >= rightMax:
                    rightMax = height[right]
                else:
                    # Water trapped above current right bar
                    water += rightMax - height[right]

                right -= 1

        return water
```

---

### Complexity

```text
Time  : O(N)

Space : O(1)
```

Every index is visited once.

---

## Why Can We Process the Smaller Side?

Suppose

```text
leftMax = 4
rightMax = 7

Current bar = 2
```

Water becomes

```text
min(4,7) - 2

= 4 - 2
```

Even if the future right boundary becomes `100`, the answer is still

```text
min(4,100) = 4
```

So the **smaller maximum completely determines the water level**, making it safe to process that side immediately.

# Key Interview Takeaways

* **Pattern:** Two Pointers + Greedy.
* **Core Formula:** `water[i] = min(leftMax, rightMax) - height[i]`.
* **Optimization:** Instead of storing prefix/suffix arrays, maintain `leftMax` and `rightMax` while moving two pointers.
* **Invariant:** Always process the side with the **smaller current maximum**, because it alone determines the water level at that side.
* **Complexity:** **O(N)** time and **O(1)** extra space.
